PERCURSO A / PARA QUEM VAI INSTALAR

Prepare o acesso
para você ou sua equipe.

Você instalará um pequeno serviço na Cloudflare. É ele que conecta o assistente ao JurisprudênciaIA e verifica quem pode entrar. A instalação é feita uma vez por servidor.

Já recebeu um endereço de acesso? Vá direto ao percurso B.

  • Contas Cloudflare e Google CloudCom permissão para criar recursos e configurar um aplicativo Google.
  • Node.js 22 ou superior e GitInstalados no computador que será usado para configurar o projeto.
  • Terminal e editor de textoPowerShell no Windows ou terminal no macOS/Linux. Um editor como VS Code facilita.
  • Uma conta Google para testarUse um endereço seu que será incluído na lista de pessoas autorizadas.

Confira as cotas e condições dos serviços que usar. Se você não costuma trabalhar com terminal, esta parte pode ser feita com apoio técnico; o uso diário começa no percurso B.

01

NO SEU COMPUTADOR

Baixe e prepare o projeto.

Abra o terminal na pasta em que deseja guardar o projeto. Confira as ferramentas instaladas:

TERMINAL · VERIFICAÇÃO
node --version
git --version

O Node deve mostrar a versão 22 ou superior. Se algum comando não for reconhecido, instale o Node.js ou o Git e abra um novo terminal.

TERMINAL · BAIXAR O PROJETO
git clone https://github.com/brunoflma/jurisprudenciaia-mcp.git
cd jurisprudenciaia-mcp
npm ci --ignore-scripts
ANTES DE CONTINUARA instalação das dependências terminou sem erro. Mantenha o terminal na pasta jurisprudenciaia-mcp para os próximos comandos. Se já tem uma cópia, use uma pasta nova para acompanhar este guia sem sobrescrever uma configuração existente.
02

CLOUDFLARE + TERMINAL

Prepare onde o conector vai funcionar.

Crie ou entre na sua conta na Cloudflare. No terminal, autorize o Wrangler, a ferramenta que publica o projeto:

TERMINAL · AUTENTICAR
npx wrangler login
npx wrangler whoami

O primeiro comando abre o navegador; conclua a autorização antes de executar o segundo. Confira se a conta exibida é a que você pretende usar.

Crie os dois espaços de armazenamento

Um guarda o cache de pesquisa; o outro, os dados de autorização. Execute um comando de cada vez e anote qual ID pertence a cada nome.

TERMINAL · CRIAR OS RECURSOS
npx wrangler kv namespace create JURIS_CACHE
npx wrangler kv namespace create OAUTH_KV

Defina o endereço do servidor

Para a primeira instalação, use o endereço workers.dev. No painel da Cloudflare, em Workers & Pages, confira ou registre o subdomínio da sua conta. Com o nome padrão do projeto, o endereço terá este formato:

EXEMPLO · TROQUE SEU-SUBDOMINIO
https://jurisprudenciaia-mcp.seu-subdominio.workers.dev

Esse endereço será a origem do servidor: começa com https:// e não tem caminho nem barra no final. Use o subdomínio real da sua conta em todos os próximos exemplos.

ANTES DE CONTINUARVocê tem os dois IDs de armazenamento e sabe qual será a origem do servidor. O nome jurisprudenciaia-mcp deve estar disponível na conta; se já existir uma instalação, escolha outro name e ajuste o endereço correspondente para não publicar por cima dela.
03

NO EDITOR DE TEXTO

Preencha os dados do seu servidor.

Abra wrangler.jsonc, na raiz do projeto. O arquivo já tem a estrutura necessária. Substitua apenas os valores indicados, mantendo as aspas e as demais configurações.

CampoO que colocar
kv_namespaces → JURIS_CACHE → idO ID criado para JURIS_CACHE.
kv_namespaces → OAUTH_KV → idO ID criado para OAUTH_KV.
vars.MCP_PUBLIC_ORIGINA origem HTTPS do servidor, sem /mcp.
vars.MCP_GOOGLE_CALLBACK_ORIGINA mesma origem, sem /oauth/google/callback.
vars.MCP_GOOGLE_CLIENT_IDSerá preenchido com o ID do Google no próximo passo.
Três endereços, três usos.Todos partem da mesma origem. O final do endereço muda conforme o lugar em que ele será usado.

Usada nos dois campos de origem do Worker.https://jurisprudenciaia-mcp.seu-subdominio.workers.dev
Retorno do Google · no Google Cloud

Já tenho um domínio próprio

Você pode usar uma origem como https://mcp.example.com. Primeiro configure esse domínio no Worker, pela opção Settings → Domains & Routes → Add → Custom Domain no painel da Cloudflare. Apenas escrever um domínio no arquivo não cria a rota.

Para a primeira instalação, conclua o percurso com workers.dev e depois faça a troca, atualizando as duas origens, o retorno do Google e os clientes. Veja a documentação de domínios da Cloudflare.

ANTES DE CONTINUAROs dois IDs foram preenchidos e os dois campos de origem contêm exatamente o mesmo endereço HTTPS. Preserve os bindings, as migrations e as outras opções do arquivo.
04

GOOGLE CLOUD + EDITOR

Prepare o login com Google.

  1. No Google Cloud Console, crie ou selecione o projeto que vai identificar o conector.
  2. Abra Google Auth Platform e configure os dados de apresentação do aplicativo e o público. Algumas interfaces mostram essas opções em APIs e serviços → Tela de consentimento OAuth.
  3. Se escolher público externo e mantiver o aplicativo em teste, confira as regras de acesso e a lista de usuários de teste em Audience / Público. Essa configuração do Google é separada da lista de pessoas autorizadas no conector.
  4. Em Clients / Clientes, crie um cliente OAuth do tipo Web application / Aplicativo da Web.
  5. Em Authorized redirect URIs / URIs de redirecionamento autorizados, cadastre a origem do servidor seguida de /oauth/google/callback, sem barra no final.
GOOGLE CLOUD · EXEMPLO DE RETORNO
https://jurisprudenciaia-mcp.seu-subdominio.workers.dev/oauth/google/callback

Troque seu-subdominio antes de cadastrar. Salve o cliente e guarde os dois valores entregues pelo Google:

Valor do GoogleOnde usar
Client ID · identificadorNo campo MCP_GOOGLE_CLIENT_ID do wrangler.jsonc.
Client Secret · segredoNo comando do próximo passo. Não coloque no arquivo de configuração ou no GitHub.
ANTES DE CONTINUARO Google tem o endereço completo de retorno. O arquivo do Worker tem apenas a origem nos campos de origem e o Client ID no campo próprio. O Client Secret ficou guardado para o próximo passo.
05

NO TERMINAL

Autorize as pessoas e publique.

Na pasta do projeto, cadastre o segredo do Google. O terminal pedirá o valor de forma interativa; cole somente o Client Secret.

TERMINAL · SEGREDO DO GOOGLE
npx wrangler secret put MCP_GOOGLE_CLIENT_SECRET

Na primeira instalação, se o Wrangler informar que o Worker ainda não existe, confirme a criação para o nome escolhido. Em seguida, cadastre a lista completa de e-mails que poderão entrar:

TERMINAL · PESSOAS AUTORIZADAS
npx wrangler secret put MCP_ALLOWED_EMAILS

Quando o terminal pedir o valor, informe os endereços completos separados por vírgula, incluindo sua conta de teste. Exemplo de formato: usuario@example.com,colega@example.com. Substitua pelos e-mails reais; não publique a lista no repositório.

Confira o projeto e publique o código

Execute a verificação. Só publique quando ela terminar sem erro:

TERMINAL · VERIFICAR
npm run verify
TERMINAL · PUBLICAR
npm run deploy:worker
ANTES DE CONTINUARO Wrangler confirmou a publicação e mostrou o endereço do Worker. Ele deve coincidir com a origem configurada. Se for diferente, ajuste as duas origens no arquivo e o retorno no Google, depois publique novamente.
06

NO NAVEGADOR

Confira se o servidor está no ar.

Abra a origem do seu servidor seguida de /healthz. Por exemplo:

ENDEREÇO · SUBSTITUA PELO SEU
https://jurisprudenciaia-mcp.seu-subdominio.workers.dev/healthz

A resposta esperada é:

RESPOSTA DO SERVIDOR
{"ok":true,"service":"jurisprudenciaia-mcp"}
Servidor no ar é a primeira confirmação.Para conferir também o login e a pesquisa, complete o percurso B e execute o teste no assistente. A página de saúde não testa o acesso ao serviço de pesquisa.

Prepare o link terminado em /mcp para cada pessoa autorizada e informe qual conta Google ela deve usar. Continue abaixo para testar seu próprio acesso.

PERCURSO B / PARA QUEM JÁ TEM ACESSO

Agora, conecte
ao seu assistente.

Você precisa de duas coisas: o link do conector, terminado em /mcp, e uma conta Google que a pessoa responsável autorizou. Se ainda não tem o link, peça à sua equipe ou siga a instalação do zero.

O endereço deste site e o link do repositório não são o endereço do conector. Use o link fornecido por quem instalou o servidor.

01

NO CLAUDE OU NO CODEX

Adicione o link do conector.

Escolha abaixo o assistente que você usa. Os nomes dos menus podem variar conforme a versão e o idioma.

Uso o Claude
  1. Abra a área de Conectores do Claude, em Personalizar / Customize. Em algumas versões, ela fica em Configurações.
  2. Use + → Adicionar conector personalizado. Informe o nome jurisprudenciaia e o endereço que você recebeu.
  3. Deixe Client ID e Client Secret vazios, caso apareçam nas opções avançadas. O conector faz o registro necessário automaticamente.
  4. Adicione o conector e clique em Conectar para iniciar a autenticação.

Em equipes, um proprietário pode precisar cadastrar o conector nas configurações da organização antes de você conectá-lo. Se a opção não estiver disponível, confira as permissões e a orientação atual do Claude.

Uso o Codex

Na área de MCPs das configurações do aplicativo, adicione um servidor Streamable HTTP chamado jurisprudenciaia, informe o link e selecione Autenticar.

Se usa a CLI, adicione o servidor com o comando abaixo, substituindo o endereço de exemplo pelo link recebido:

TERMINAL · ADICIONAR NO CODEX
codex mcp add jurisprudenciaia --url https://jurisprudenciaia-mcp.seu-subdominio.workers.dev/mcp

Depois, inicie o login:

TERMINAL · ENTRAR COM GOOGLE
codex mcp login jurisprudenciaia

Se o servidor já foi adicionado, basta fazer o login. Para ajustar o tempo de espera das ferramentas a 120 segundos ou conferir a configuração completa, veja o guia técnico do Codex.

02

NO NAVEGADOR

Entre com a conta autorizada.

  1. Confira se a página de autorização pertence ao servidor que você pretende usar.
  2. Escolha Continuar com Google e selecione a conta que foi autorizada pela pessoa responsável.
  3. Conclua a autorização e volte ao assistente. No Codex, mantenha o aplicativo ou terminal aberto durante o login.
O QUE VOCÊ DEVE VERO assistente confirma a conexão ou a autenticação. Abra uma conversa nova, habilite o conector se necessário e faça a pesquisa de teste abaixo.
03

EM UMA NOVA CONVERSA

Faça a primeira pesquisa.

Comece com um tema genérico. Copie o pedido e envie ao assistente com o conector habilitado:

PEDIDO DE TESTE
Use a ferramenta pesquisar_jurisprudencia do conector jurisprudenciaia para pesquisar negativação indevida e dano moral no STJ. Informe as fontes retornadas e sinalize quando uma informação não estiver disponível. Não complete dados ausentes.
  1. Confira a chamada da ferramenta. O assistente deve executar pesquisar_jurisprudencia; uma resposta apenas do modelo não confirma o funcionamento do conector.
  2. Confira o resultado da execução. Erros de autenticação, tempo de espera ou indisponibilidade precisam ser resolvidos. Uma pesquisa sem resultados também deve ser apresentada como tal.
  3. Abra e confira as fontes disponíveis. Antes de usar qualquer resultado em uma peça, valide a decisão e sua pertinência na fonte oficial.
Ver a lista de ferramentas não basta.A lista pode estar em cache. A confirmação útil é uma nova chamada concluída, autenticada, com o retorno da pesquisa — inclusive quando ele informa que não encontrou resultados.

Depois do teste, explore os roteiros de uso no dia a dia.

SE ALGUMA ETAPA NÃO FUNCIONAR

Encontre o próximo ajuste.

Não sei qual link colocar no assistente

Use o endereço do servidor publicado, terminado em /mcp. Peça esse link a quem instalou o conector. A página github.io é este guia; o repositório github.com guarda o código. Nenhum dos dois substitui o servidor.

O Google mostrou “redirect_uri_mismatch”

No Google Cloud, o retorno autorizado precisa ser a origem HTTPS seguida de /oauth/google/callback. Já MCP_GOOGLE_CALLBACK_ORIGIN, no arquivo do Worker, contém somente a origem. Confira domínio, HTTPS e ausência de barra final. Se alterar o arquivo, publique novamente. Não cadastre o retorno temporário local do Codex no Google.

Minha conta Google não foi autorizada

Confira se escolheu a conta correta. A pessoa responsável precisa incluir esse e-mail completo em MCP_ALLOWED_EMAILS. Ela também deve conferir o público, as restrições e, quando aplicável, os usuários de teste do aplicativo Google. Ter acesso ao Claude ou Codex não autoriza automaticamente o uso deste servidor.

Como adicionar outra pessoa à equipe?

Quem administra o servidor executa novamente npx wrangler secret put MCP_ALLOWED_EMAILS e informa a lista completa, incluindo os e-mails anteriores e o novo. O comando substitui o valor inteiro e publica uma nova versão do Worker. Depois, a pessoa recebe o link e faz seu próprio login Google.

O assistente mostra falha de conexão

Confira o endereço terminado em /mcp e verifique se /healthz responde. Se a publicação estiver correta, reconecte o assistente e refaça o login. Quem administra pode seguir o diagnóstico de implantação. A resposta de saúde confirma o Worker, mas não garante que todos os serviços externos estão disponíveis.

A ferramenta aparece, mas a consulta falha ou demora

Confira o resultado da chamada, a validade da autenticação e a disponibilidade do serviço de pesquisa. No Codex, o guia de configuração mostra como usar tool_timeout_sec = 120. Não interprete uma lista de ferramentas carregada como prova de uma pesquisa executada.

Meu aplicativo só aceita um conector local

Esse é um caminho avançado. Consulte a configuração com mcp-remote para clientes que precisam de uma ponte local. No Claude e no Codex com conexão remota, siga o percurso B deste guia.

Como pedir ajuda sem expor minha configuração?

Descreva a etapa, o assistente usado e a mensagem de erro no GitHub. Remova senhas, Client Secret, tokens, cookies, códigos OAuth, e-mails e dados de processos das capturas. Os exemplos visuais deste guia são ilustrativos e não representam contas reais.
