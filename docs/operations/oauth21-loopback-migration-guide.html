MCPs privados · Cloudflare Workers

Como deixar todos os MCPs prontos para OAuth 2.1 e aplicativos locais

Este roteiro permite usar o mesmo MCP no Claude web e em aplicativos locais, como Claude-3p com mcp-remote, sem abrir callbacks inseguros.

Claude-3p→mcp-remote→Worker MCP

O mcp-remote inicia um pequeno servidor no seu computador. Ele escolhe uma porta livre, por exemplo 127.0.0.1:3334, recebe o retorno do login e entrega a conexão ao Claude-3p.

O que precisa mudar

O Worker precisa aceitar dois tipos seguros de retorno após o login:

UsoCallback aceitoProteção
Claude na webhttps://claude.ai/api/mcp/auth_callback ou https://claude.com/api/mcp/auth_callbackURL HTTPS exata
Claude-3p e aplicativo localhttp://127.0.0.1:<porta>/oauth/callback ou http://localhost:<porta>/oauth/callbackCliente público + PKCE S256
NÃO ACEITAR IP de rede, 0.0.0.0, IPv6, caminhos diferentes, parâmetros na URL ou domínios parecidos. O loopback é seguro porque aponta de volta para o computador do próprio usuário.

Passo a passo

1. Trabalhar no local certo

Faça a migração somente no repositório privado. Não publique o código no repositório público enquanto a validação não estiver concluída. Nunca coloque tokens, Client Secrets ou chaves em arquivos versionados.

2. Ajustar a regra OAuth

O código deve aceitar somente os callbacks da tabela. Para aplicativo local, a porta pode mudar; por isso o Worker valida o host, uma porta válida e o caminho exato /oauth/callback.

O nome declarado pelo aplicativo, como “Claude”, não prova sua identidade e não deve ser usado como regra de segurança.

3. Exigir proteção extra no aplicativo local

O cliente local não usa Client Secret. Ele deve usar OAuth Authorization Code com PKCE S256. Essa proteção impede o uso indevido de um código de autorização interceptado.

4. Manter Google e a allowlist

O Google continua retornando para o domínio HTTPS público do Worker. O Worker então entrega o resultado ao callback local autorizado. A lista privada de e-mails permitidos continua obrigatória.

5. Rodar testes antes de publicar

npm test -- tests/worker.test.ts tests/oauth-google.test.ts
npx wrangler deploy --dry-run

Os testes provam que callbacks corretos funcionam e os inseguros são recusados. O dry-run confere bundle e configurações sem publicar nada.

6. Publicar só o Worker

npx wrangler deploy

Esse comando atualiza a Cloudflare, mas não faz commit nem envia código ao GitHub.

7. Conferir a produção

npm run check:loopback-oauth

O resultado correto é:

Loopback OAuth OK: discovery, DCR publico, porta dinamica e PKCE S256 validados.

Configurar o Claude-3p

{
  "mcpServers": {
    "nome-do-mcp": {
      "command": "npx",
      "args": [
        "-y", "mcp-remote@latest", "https://SEU-DOMINIO/mcp",
        "--host", "127.0.0.1", "--transport", "http-only", "--auth-timeout", "120"
      ]
    }
  }
}
  1. Salve a configuração e reinicie o Claude-3p.
  2. Quando o navegador abrir, confirme o aviso de Aplicativo local.
  3. Entre com uma conta Google presente na allowlist.
  4. Volte ao Claude-3p e confirme que as ferramentas aparecem.

Problemas comuns

“Callback ou metadados OAuth não permitidos”

O Worker publicado ainda está com a regra antiga ou o callback não segue o formato seguro. Rode o teste público, confira o domínio e publique o bundle validado. Não libere qualquer URL local para contornar isso.

“Autorização inválida” depois do Google

Confira se a conta está na allowlist, se os secrets Google existem e se o callback HTTPS cadastrado no Google coincide exatamente com o domínio do Worker.

O secret parece salvo, mas o Worker não funciona

No Windows, não envie secrets por pipeline para wrangler secret put. Digite o valor no prompt interativo e valide o Worker depois do deploy. A mensagem de sucesso não prova o conteúdo do secret.

O Claude-3p insiste em conexão antiga

Feche o aplicativo e limpe apenas o estado daquele MCP na pasta local .mcp-auth. Não apague a configuração dos outros conectores.

Checklist final

  • Callbacks web exatos continuam funcionando.
  • Loopback aceita somente 127.0.0.1 ou localhost, porta dinâmica e /oauth/callback.
  • Loopback exige cliente público e PKCE S256.
  • Testes e dry-run passaram.
  • Worker privado foi publicado e o teste público passou.
  • Claude-3p concluiu o login e carregou as ferramentas.
  • Nenhum segredo foi exposto e nenhum repositório público foi atualizado antes da validação.
